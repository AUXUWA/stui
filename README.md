[![CI](https://github.com/AUXUWA/stui/actions/workflows/ci.yml/badge.svg)](https://github.com/AUXUWA/stui/actions/workflows/ci.yml)
[![Release](https://img.shields.io/github/v/release/AUXUWA/stui?label=release)](https://github.com/AUXUWA/stui/releases/latest)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![Rust](https://img.shields.io/badge/rust-2024%20edition-orange.svg)](https://www.rust-lang.org)

**A terminal serial-port tool with both a TUI and a script/AI-friendly CLI.**

`stui` is a serial-port debugger written in Rust. It ships two front-ends over one
shared parsing and port layer, so the command line and the interface behave
identically:

- a **TUI** for humans — send and receive on one screen, filter, hex view,
  follow the tail, record to a file;
- a **CLI** for scripts and AI agents — structured JSON on stdout, meaningful
  exit codes, and a built-in loopback device so the whole link can be
  self-tested without any hardware.

一个用 Rust 写的串口调试工具，同时提供 **TUI 交互界面** 和 **面向脚本 / AI 的 CLI 模式**，
共用同一套解析与端口逻辑，因此命令行和界面里的行为完全一致。

```
 stui  串口终端工具  ● 已连接
┌ 串口参数 ──────────────┐  终端  │  日志  │  统计  │  帮助
│▸ 端口      COM25 ◀▶    │┌ 收发 · 文本 · 自动滚动 · 缓冲 26 B ────────────────┐
│  波特率    115200       ││04:03:34.401 RX▾ AT+VERSION?                       │
│  数据位    8            ││04:03:34.401 TX▴ AT+VERSION?                       │
│  校验      无           ││                                                       │
│  流控      无           ││                                                       │
│  打开串口  ■ 关闭串口   │└───────────────────────────────────────────────────────┘
│                       │┌ 输入 ▶ Enter 发送 · \r \n \xNN 转义 ──────────────────┐
│                       ││$                                                       │
│                       │└───────────────────────────────────────────────────────┘
│                       │┌ 状态 ────────────────────────────────────────────────┐
│                       ││待发送 14 字节  循环 关 1000 ms                       │
└───────────────────────┘└───────────────────────────────────────────────────────┘
 ● COM25 · 115200 8N1 · 无流控 RX 128 B / 13 包 · TX 12 B · 20fps              21:41:06
```

## 特性

- **端口与参数**：自动枚举串口（Windows `COMx` / Linux `ttyUSB*` / macOS `cu.*`），可调波特率、数据位、校验、停止位、流控；已连接时改参数会提示需重开。
- **收发同屏**：接收与发送在同一个「终端」页里按时间顺序排列，行首用 `RX▾` / `TX▴` 标明方向；输入框就在数据区下方，边看边发，不用切页。
- **行合并**：设备一个字节一次地发（AT 指令、按键回显）也会合并成**一行**，只有遇到真实换行或空闲 180 ms 才另起一行 —— 不会再出现「一个字符占一行」。
- **数据显示**：串口数据一律按 **UTF-8** 解码，中文、emoji 原样显示；控制符以 `^M` 形式显示（占 2 列）；只有真正非法的字节才降级成 `·`。列宽按 `unicode-width` 计算，切行与截断都不会把字符劈开。
- **转义折叠**：设备发的 ANSI 彩色日志（Python / Node / ESP32 等）里的 `ESC[…` 序列统一折叠成定宽的 `^[m`，不会刷成一屏 `^[[31m` 垃圾；想看原始字节随时切 HEX 视图。
- **换行规则**：文本模式严格按数据里的 `\n`（含其前导 `\r`）分行，孤立的 `\r`（回车覆盖、进度条刷新）不切行、不按屏宽硬折；单行超宽时截断并以 `…` 提示（按 `w` 可打开**长行自动折行**，改成折成多行、一行数据都不丢）。行尾换行不会多出一个空行。
- **HEX 视图**：偏移 + 十六进制 + 预览栏，每行字节数随宽度自适应（16 / 8 / 4）。
- **发送**：支持 `\r \n \t \0 \e \\ \xNN` 转义、中文按 UTF-8 发送；可切 HEX 模式输入 `41 42 43`；支持循环发送与整文件发送。
- **发送历史**：输入框里 `Ctrl+↑` / `Ctrl+↓` 在最近 100 条发送内容之间翻；存的是**你当时敲的原文**，翻过最新一条会回到翻历史之前的输入内容。
- **自动重连**：`Ctrl+R` 开关。掉线后每 2 秒按当前参数重试一次，连着失败 5 次才记一条日志（不刷屏）；手动断开**不会**关掉它，断开时日志里会明确提示「自动重连仍开启」。
- **时间戳精度**：`Ctrl+T` 在「显示到毫秒」与「只到秒」之间切换。关掉毫秒后行首前缀用空格补齐，宽度恒定，数据列不会左右跳。
- **关键字过滤与高亮**：`/` 输入关键字，按**记录**过滤（命中记录整条完整显示，不打乱行结构）；数据区里命中的片段用高亮底色标出，一眼能看出命中的是哪几个字。
- **过滤的三个维度**：关键字之外还有**忽略大小写**（`I`）与**排除匹配**（`!`）两个开关，可以单用也可以叠加；当前模式在面板标题里用 `i` / `!` 标出来，统计页也单列一行「过滤选项」，不会「看着像显示命中的、其实是排除命中的」。
- **长行自动折行**：按 `w` 开关。关着时超宽的行照旧截断并标 `…`（默认行为），开着时按屏宽把长行折成多行、后续行缩进对齐，超宽的行也一行数据都不丢。
- **记录详情弹窗**：数据区按 `Enter` 打开，把当前顶着的那条记录摊开看（按弹窗宽度折行，不横向截断）；弹窗里 `↑` `↓` 翻相邻记录、`v` 切 HEX 视图、`Esc` / `Enter` 关闭。
- **过滤命中导航**：`n` 跳到下一条命中的记录、`N` 跳到上一条。屏幕顶上那条记录有底色，面板标题里也写着「第几条」，一眼知道自己停在哪。（排除模式下命中的是那些**没显示**的记录，导航跳的是屏幕上有的那些，快捷键面板会写成「跳未命中」。）
- **自动刷新端口列表**：每 5 秒枚举一次串口，**列表真的变了才记一条日志**（插上 / 拔掉设备会看到提示）；列表没变化时一条都不记，跑上几小时也不会把日志刷满。
- **鼠标滚轮**：终端里直接用滚轮上下滚数据区（一格 3 行，与方向键同语义、同样会关掉自动跟随），日志 / 统计 / 帮助页滚的是同一个滚动位置。点击、拖拽一律不响应 —— 界面上没有「点哪儿跳哪儿」的交互。
- **统计页**（页签 `3`）：会话时长、收发字节与包数、当前速率、缓冲占用条、串口参数、当前视图与过滤状态、自动重连 / 刷新率等开关状态，一屏看完本次会话。
- **配置持久化**：启动时读 `~/.config/stui/config.json`（Windows 是 `%APPDATA%\stui\config.json`），退出时把当前端口与参数写回；`--no-config` 可以完全跳过读写。
- **记录**：一键把收发明细按时间戳写入 `logs/stui-YYYYMMDD-HHMMSS.log`。
- **弱链路友好**：脏标记重绘（界面没变就不画）+ `--fps` 帧率上限 + 每帧只切分可见范围内的记录，SSH / 容器 / 网页终端里也不会卡。
- **CLI 模式**：`--json` 输出结构化结果与明确退出码，可直接被脚本或 AI 调用；内置 `sim` 虚拟回环设备，无硬件也能端到端自测。
- **编码统一**：源码、文档、日志一律 UTF-8 无 BOM + LF；Windows 下启动时自动把控制台切到 UTF-8 代码页 65001。

## 安装

### 预编译二进制

从 [Releases](https://github.com/AUXUWA/stui/releases) 下载对应平台的压缩包，
解包即用，不需要 Rust 工具链：

| 平台 | 压缩包 |
| --- | --- |
| Windows x86_64 | `stui-v0.1.0-windows-x86_64.zip` |
| Linux x86_64 | `stui-v0.1.0-linux-x86_64.tar.gz` |
| macOS (Apple Silicon) | `stui-v0.1.0-macos-aarch64.tar.gz` |
| macOS (Intel) | `stui-v0.1.0-macos-x86_64.tar.gz` |

Windows 上解压后直接跑 `stui.exe`；Linux / macOS 上 `tar -xzf` 之后给二进制加个
可执行权限（`chmod +x stui`）即可。

### 从源码构建

需要 Rust 2024 edition（1.85 及以上）。

```bash
git clone https://github.com/AUXUWA/stui.git
cd stui
cargo build --release        # 产物在 target/release/stui(.exe)
cargo test                   # 单元测试 + CLI 契约测试
```

`cargo test` 里除了单元测试，还有一组**面向脚本 / AI 的命令行契约测试**；
另有一个独立校验器 `scripts/verify.mjs`，不经过 cargo、直接拿构建好的二进制
逐条验退出码与 JSON 字段：

```bash
cargo build --release && node scripts/verify.mjs target/release/stui.exe
```

## 一、TUI 交互模式

```bash
stui                                  # 直接进入界面
stui -p COM25 -b 9600 -o              # 预选端口并立即打开
stui --fps 10                         # 远程/容器终端里卡顿时把刷新上限压到 10 帧
stui --no-config                      # 不读也不写配置文件，用默认设置跑一次
stui --version                        # 打印版本号
stui --help                           # 打印完整按键与参数说明
```

界面内按 `F1` 查看完整按键表。焦点在**三档**之间循环（这是最容易卡住的地方，所以显式说明）：

```
终端页（页签 1）：
参数栏  ──Tab──▶  输入框  ──Tab──▶  数据区  ──Tab──▶  参数栏
                          ↑                  │
                          └───── Esc ────────┘（不在输入框时，Esc 收回参数栏）

其它页签（日志 2 / 统计 3 / 帮助 4）没有输入框，只有两档：
参数栏  ──Tab──▶  数据区  ──Tab──▶  参数栏
```

输入框是单行的，**上下键不会插到输入框里**，而是直接用来滚动上方的数据区。

### 页签

| 页签 | 数字键 | 内容 |
| --- | --- | --- |
| 终端 | `1` | 收发合一的流 + 发送输入框 + 状态区 |
| 日志 | `2` | 事件日志（只列 `SYS` 记录），`x` 可清空 |
| 统计 | `3` | 本次会话的量、速率、占用与开关状态 |
| 帮助 | `4` | 完整按键表 |

`F1` / `F2` / `F3` 都**直接打开帮助页**（等同按 `4`），没有单独的 F1 键位。数字键在**输入框以外**都是切页签；焦点在输入框时它们是普通字符，会被当作待发送数据。

### 按键表

「生效焦点」一列说的是这条键**在哪个焦点下才会被响应**。同一个物理键在不同焦点下含义可能不同 —— 比如 `↑` `↓` 在参数栏下是选择设置项，在数据区与输入框下才是滚动数据区；输入框里的可打印字符一律是待发送数据，不会被当成命令。

| 按键 | 作用 | 生效焦点 |
| --- | --- | --- |
| `Tab` | 参数栏 → 输入框 → 数据区 → 参数栏（其它页签只有参数栏 ↔ 数据区两档） | 任意 |
| `Ctrl+Tab` | 直接跳到数据区 | 任意 |
| `Shift+Tab` | 与 `Tab` 同向切换（代码里走同一条分支，不反向） | 任意 |
| `1` `2` `3` `4` | 切换页签：终端 / 日志 / 统计 / 帮助 | 输入框以外 |
| `F1` / `F2` / `F3` | 直接打开帮助页（等同 `4`） | 输入框以外 |
| 直接输入 | 焦点在输入框时，可打印字符都是待发送数据，中文按 UTF-8 | 输入框 |
| `PgUp` / `PgDn` | 按可视高度翻页滚动数据区 | 输入框、数据区 |
| `Esc` | 输入框焦点下发送 `0x1B`；有过滤时先取消过滤；其余位置把焦点收回参数栏；**详情弹窗**开着时只关弹窗，不会顺手取消过滤 | 任意 |
| `↑` `↓` | 在数据区 / 输入框下是**滚动数据区**；在参数栏下是**选择设置项**（`k` `j` 同义） | 任意 |
| `←` `→` | 在参数栏下是**修改选中项的取值**（`h` `l` 同义）；在输入框下是光标移动 | 输入框、参数栏 |
| `Home` / `End` | 终端页数据区：`Home` 跳到开头、`End` 到底并恢复跟随；其它页签 `Home` 回到顶部；输入框里是光标移动 | 输入框、数据区 |
| `Enter` | 在输入框里发送内容；在参数栏里打开 / 关闭串口；在**终端页数据区**里打开**记录详情弹窗** | 输入框、参数栏、数据区 |
| `a` | 切换 / 恢复**自动跟随**最新数据（滚到底部也会自动恢复跟随） | 数据区 |
| `Ctrl+End` / `Ctrl+A` | 恢复自动跟随（任何焦点下都能用） | 任意 |
| `p` | **暂停 / 恢复跟随**：数据照收不误，但画面停住不追新（滚动也不会解除暂停） | 输入框以外 |
| `/` | **按关键字过滤**，`Enter` 应用、`Esc` 取消；按记录过滤，整条记录完整显示 | 输入框以外 |
| `I` | **过滤忽略大小写**开关：比较时 ASCII 字母不分大小写（`error` 也能命中 `ERROR`），标题里标 `i` | 输入框以外 |
| `!` | **排除匹配**（反向过滤）开关：命中关键字的记录**不显示**，只留没命中的，标题里标 `!` | 输入框以外 |
| `v` | 文本 ⇄ HEX 视图切换 | 数据区 |
| `w` | **长行自动折行**开关：超宽的行按屏宽折成多行（关着时照旧截断并标 `…`） | 输入框以外 |
| `n` / `N` | **过滤命中导航**：跳到下一条 / 上一条命中的记录（不过滤时就是相邻记录；到头就停住，不循环）。**排除模式**下命中的是那些**没显示**的记录，导航跳的是屏幕上有的那些（即「未命中」的记录），快捷键面板会相应写成「跳未命中」。**只在终端页有效**，别的页签按会提示「切到终端页」 | 输入框以外 |
| `x` | 清空缓冲（**收发 + 事件日志全清**）；日志页里同样是清空 | 数据区、日志页 |
| `c` | **只清空接收区**：删掉收到的数据，发送记录与事件日志保留；累计统计不清零 | 输入框以外 |
| `l` | 开始 / 停止记录（`logs/` 目录） | 数据区 |
| `o` | 断开 ⇄ 连接 | 数据区、日志 / 统计 / 帮助页 |
| `r` | 重新枚举串口（**不是**自动重连） | 参数栏 |
| `Ctrl+R` | **自动重连**开关：掉线后每 2 秒重试一次 | 输入框以外 |
| `Ctrl+T` | **时间戳**显示到毫秒 / 只到秒 | 输入框以外 |
| `Shift+F` | 切换界面刷新上限（5 / 10 / 20 / 30 帧），当前值显示在状态栏 | 输入框以外 |
| `Ctrl+H` / `Ctrl+L` | HEX 输入模式（**会自动转换已有内容**）/ 循环发送 | 输入框 |
| `Ctrl+↑` / `Ctrl+↓` | 在**输入框**里翻发送历史 | 输入框 |
| `Ctrl+↑` / `Ctrl+↓` | 在**其它焦点**下减小 / 增大循环间隔（-50 / +50 ms） | 输入框以外 |
| `Ctrl+[` / `Ctrl+]` | 减小 / 增大循环间隔 | 任意 |
| `Ctrl+O` / `Ctrl+U` | 发送整个文件（需已连接）/ 清空输入框 | 任意 |
| `Ctrl+Q` | 退出程序 | 任意 |
| `q` | 退出程序 | 输入框以外 |
| `↑` `↓`（弹窗内） | 在**记录详情弹窗**里翻上一条 / 下一条记录（只在命中的记录之间翻，到头就停住） | 详情弹窗 |
| `v`（弹窗内） | 在**记录详情弹窗**里切文本 / HEX 视图 | 详情弹窗 |
| `Esc` / `Enter`（弹窗内） | 关闭**记录详情弹窗**（`Esc` 只关弹窗，不会顺手把过滤也取消） | 详情弹窗 |
| 鼠标滚轮 | 上下滚动数据区（一格 3 行），语义与方向键完全一致、同样会关掉自动跟随；日志 / 统计 / 帮助页滚同一个滚动位置。**详情弹窗开着时不响应** | 任意 |

接收缓冲区上限 4 MiB / 2 万条记录，超出后自动丢弃最旧的数据，不会无限吃内存。

**`w`、`n`、`N`、`I`、`!` 这几个键在输入框焦点下是普通字符**（会被当作待发送数据，和 `1` `2` `3` `4` 一样），只有焦点在参数栏 / 数据区时才是命令 —— 正在敲一条 AT 指令时打 `n` 不会误触发跳转。`I` 是大写字母（`Shift+i`）、`!` 是 `Shift+1`，两个键都要**大写 / 带符号**才生效。

### 过滤

`/` 打开过滤框输入关键字，`Enter` 应用、`Esc` 取消。过滤是**记录级**的：命中的记录整条完整显示，不会打乱行结构。

过滤由三个维度组成，可以任意组合：

| 维度 | 键位 | 作用 |
| --- | --- | --- |
| 关键字 | `/` | **正向**模式下：显示文本里**包含**关键字的记录（排除模式下这一行正好反过来） |
| 忽略大小写 | `I` | 比较时 ASCII 字母不分大小写（`error` 也能命中 `ERROR`）；非 ASCII 字符（中文）本来就没有大小写，按原样比较 |
| 排除匹配 | `!` | **反向过滤**：命中关键字的记录**不显示**，只留没命中的 |

- **关键字为空就是不过滤**：两个开关照样留着（标题里显示「过滤选项 [i!]」），但一条记录都不筛掉 —— 开关随时能改，正在看命中结果时想起要排除某类数据，不用先把过滤取消掉再来一遍。
- **两个开关可以叠加**：`I` + `!` = 排除「忽略大小写后命中关键字」的记录。
- **切换任一开关都会复位滚动位置**（命中集合变了，之前的行号没有意义），并弹一条提示说明当前模式；面板标题里的 `i` / `!` 标记与统计页的「过滤选项」一行也会同步更新。
- **判据用的是显示文本**：控制符显示成 `^X`、非法字节显示成 `·`、转义序列折叠成 `^[m`，高亮用的是同一份表示，所以不会出现「算命中却找不到高亮」；而且是按**逻辑行**判命中（不是把整条记录拼成一段再判），关键字横跨两行时也能高亮得出来。
- **空结果的提示语分三种**：本来就没有数据时是「（暂无数据，连接串口后收发都会显示在这里）」；正向模式没命中时是「（没有匹配「关键字」的记录，按 Esc 取消过滤）」；**排除模式**且每条记录都命中了关键字时才是「（已排除「关键字」，没有可显示的记录，按 Esc 取消过滤）」—— 说「已排除」等于断言了一件确实发生过的事，说「没有匹配」会让人以为关键字写错了。
- **排除模式下 `n` / `N` 跳的是「未命中」的记录**：命中关键字的那些被排除掉了、根本不在屏幕上，导航只能在屏幕上有的记录之间跳；快捷键面板会相应写成「n/N 跳未命中」。
- **数据区里的 `Esc` 清掉的是关键字**，两个开关本身不受影响（要关掉再按一次 `I` / `!`）；过滤框里的 `Esc` 只是放弃这次编辑，已经生效的过滤不变。两个开关会被写进配置文件，下次启动照旧生效。

### 远程 / 容器终端里很卡怎么办

SSH、容器 exec、网页终端这类弱链路上，界面每一次重绘都要过一次网络，所以 stui 做了三道限速：

1. **脏标记重绘**：界面可见状态没变时一帧都不画，空闲时基本零输出。
2. **帧率上限**：`--fps <n>`（默认 20）或界面里按 `Shift+F` 在 5 / 10 / 20 / 30 之间切。当前值一直显示在状态栏末尾（`… · 20fps`），用来区分"程序画得慢"还是"链路传得慢"。
3. **只为可见范围切分**：界面每帧只用**缓存的行数**定位，落在可视区之外的记录整条跳过、从不切分；落在可视区里的记录用惰性迭代器逐行产出，不预先把整条记录切成 Vec。一条几千行的记录在屏幕上只占几十行，切分开销也就只按这几十行算。

除这三道限速外，每帧的开销还有几处刻意压过：

- **显示形态惰性缓存**：一条记录的「显示文本 / 各行文本 / 各行列宽」只算一次就缓存起来，**过滤判命中与渲染画行共用这同一份**（不会出现「过滤按一套文本判命中、画面画的是另一套」）；只有数据真的变了（追加字节 / 截尾）才作废重算。
- **一帧只扫一遍过滤**：每帧先把命中的记录收成一份，行数统计、画行、命中导航全都复用它 —— 统计与绘制各扫一遍的话，字节扫描开销直接翻倍。
- **折行时统计与渲染同源**：打开长行折行后，「这条记录占几行」与「这条记录画成什么样」走的是同一套走法（宽字符整体挪行、空列怎么算都一致），行数不会算少，滚到底不会错位。
- **折行行数带缓存**：折行模式下「这条记录占几行」的结果按「(记录, 折行宽度)」缓存一格。面板宽度很少变，于是每帧只剩一次查表，**每帧成本不再随缓冲内容线性增长**；只有面板宽度变了（改窗口大小）或那条记录的数据变了（追加字节 / 截尾）才重算那一条。

行数统计不随缓冲大小线性增长（换行个数随数据增量维护，每帧统计 2 万条记录约 0.02 ms），所以卡顿基本只来自网络传输，降 `--fps` 即刻见效；降到 5 帧也完全够看清串口数据。**开了长行折行也一样**：折行后的行数是缓存出来的，宽度不变时每帧不再重扫内容，开销与缓冲里有多少字无关（首次显示与改窗口大小时那一次重算除外，见「已知限制」）。

## 二、CLI 模式（脚本 / AI 接入）

`stui <子命令>` 走非交互路径，加 `--json` 后所有结果（含错误）都是 stdout 上的单行 JSON。

```bash
stui list    [--json] [--kind usb|bluetooth|pci] [--verbose]
stui ports   [--json] [--kind usb|bluetooth|pci] [--verbose]
stui send    --port <名> [--baud n] [--bits 5-8] [--parity none|odd|even]
                      [--stops 1|2] [--flow none|hardware|software]
                      [--text <串>] [--hex <十六进制>] [--file <路径>]
                      [--repeat n] [--interval ms] [--wait ms] [--bytes n]
                      [--expect <十六进制[|十六进制…]>] [--expect-timeout ms]
                      [--dry-run] [--json]
stui listen  --port <名> [--baud n] [--timeout ms] [--bytes n] [--idle ms]
                      [--format ndjson|text] [--save <路径>] [--json]
stui watch   --port <名> [--baud n] [--timeout ms] [--interval ms] [--json]
stui record  --port <名> [--baud n] [--out <路径>] [--duration ms]
                      [--format ndjson|text] [--stdout] [--json]
stui selftest [--json]
stui sim     [--pattern <十六进制>] [--count n] [--interval ms] [--duration ms] [--json]
```

要点：

- `--text` 走与 TUI 相同的转义解析，`--hex` 接受 `41 42 43`、`0x41-0x42`、`4142`；`--file` 读取整个文件并追加发送；三者可组合，拼接顺序固定为 **文件 → HEX → 文本**。
- `--repeat` / `--interval` 做周期性发送，`--wait` / `--bytes` 控制发送后等回显多久。
- `--port sim` 指向内置的进程内回环虚拟设备，**无需任何硬件**即可验证链路（发送什么就回什么），也是自动化测试的基础。
- `sim` 启动后会向 stderr 打印一行 `stui-sim ready`，脚本可据此判断就绪。
- `ports` 是 `list` 的**别名**，走完全相同的代码路径，输出与退出码一致。
- `list --kind usb|bluetooth|pci` 按端口描述分类过滤。分类规则很简单：描述里含「蓝牙」算 `bluetooth`，含「PCI」算 `pci`，其余一律算 `usb`；`--kind` 传别的值是参数错误（退出码 2）。
- `list --verbose` 只影响**人看的输出**：端口后面多出「厂商 / 产品」两列（`COM26       USB-SERIAL CH340 (COM26) wch.cn | 厂商: wch.cn | 产品: CH340`）。`--json` 里本来就有 `manufacturer` / `product` 两个字段，不需要这个开关。
- `send --dry-run` **只解析不发送**：不打开串口，`--port` 可以省略。JSON 里 `sent` 恒为 `0`，另有两个字段描述「将要发什么」：`planned`（字节数）与 `planned_hex`（紧凑十六进制）。dry-run 只跳过「发送 / 等待」这个动作，**参数本身照样校验**：`--repeat 0`、`--bytes abc` 这类非法取值在 dry-run 下同样是退出码 `2`。
- `send --expect <十六进制>` 校验设备回包：发完之后等一段时间，收到的字节里**包含**期望序列就算成功。写法与 `--hex` 是同一套（`41 42`、`0x41-0x42` 都认），空目标按参数错误处理（退出码 2）。**一段里逗号仍是字节分隔符**：`--expect "41,42"` 是**一根连续的 2 字节**针脚（与 `--hex "41,42"` 完全等价），不是两根各 1 字节的针脚。
- `send --expect` 可以给**多个期望**，用**竖线** `|` 分隔（`--expect "41 42|FF"`）：收到的数据必须**同时**包含每一段才算通过 —— 是「与」不是「或」，设备只回了一段说明它还没把话说完。每一段各自走与 `--hex` 相同的十六进制写法；有一段不合法，整个参数就不合法（退出码 2，错误信息里带「第几段」）：校验目标不能只校验一半。
  - 分隔符为什么不是逗号：逗号在 `--hex` 那套写法里已经分隔「一段之内的字节」，再拿它当「段与段」的分隔符，同一个字符就有两种含义 —— `--expect "41,42"` 会从「一根 2 字节针脚」悄悄变成「两根独立针脚」（任意顺序、任意位置命中即可），**校验被静默放宽**。竖号不在那套分隔符里，旧写法一字未变。
  - 尾随的 `|`（`--expect "41|"`）不算一段，忽略掉；中间出现空段（`--expect "41||42"`）是笔误，报参数错误并指出是第几段。
- `send --expect-timeout <ms>` 是等回包的时限，**不给就复用 `--wait`**（"等多久算超时"只有一个来源，不会两个参数各说各话）；单独给而没有 `--expect` 是参数错误。回包没等到时退出码是 **5**（不是 1）。
  - 这个时限同时管两件事：**收包到什么时候为止**，以及**哪些字节算命中** —— 收包窗口不会超过它（`--expect-timeout 100 --wait 3000` 约 100 毫秒就收工，不会被 `--wait` 架空），时限之后才到的字节不算命中。
- `send` 的 JSON **恒带** `expect_ok` / `expect_hex` / `expect_checked` / `expect_missing` 四个字段：没用 `--expect` 时分别是 `true`、空串、`false` 与空数组 `[]`，脚本可以按固定 schema 取值，不必先判断这一轮到底有没有用 `--expect`。`expect_ok` 只说「有没有失败」，`expect_checked` 才说「**到底校没校验**」—— `--dry-run` 什么都没发也就什么都没校验，这时 `expect_checked` 是 `false`（`expect_ok` 仍然是 `true`，因为没有失败可报）。
- 多期望下 `expect_hex` 是各段紧凑十六进制的**逗号连接**（单期望时与从前一字不差：`"4142"`；多段时 `"4142,FF"`）；`expect_missing` 列出**没命中**的那几段（紧凑十六进制组成的数组，全部命中时是 `[]`）—— `expect_ok=false` 只说「没齐」，`expect_missing` 才说清「差哪几段」。
- `listen --format ndjson` 是**流式**输出：来一块冲一行 JSON（`t` / `len` / `rx_hex` / `rx_text`），收尾再冲一行带 `"done":true` 的汇总；收不满时最后一行是 `"ok":false` + `"error":"timeout"`。`--format text`（默认）是一次收完再输出，与从前完全一样；两种格式的**收包语义相同**，只是「每块数据怎么写」不同。
- `listen --save <路径>` 把收到的字节**原样**写进文件（与 `record` 的落盘语义一致：不解码、不转义、不补换行），而且是**边收边写** —— 超时退出时已经收到的数据也不会丢。给了 `--save` 时结果 JSON 里多一个 `out` 字段（保存到的路径），不给则与从前一字不差。`listen` 的落盘参数是 `--save`（`record` 才是 `--out`），混用会报「未知参数」（退出码 2）；文件打不开或写失败是运行错误（退出码 1）。
- `watch` 是**长时监听**：来一块输一块。`--timeout` 是总时长（毫秒，默认 `0` 表示不设截止时间，一直监听到进程被结束），`--interval` 是轮询粒度（单次等待一块数据的最长时间，默认 1000 ms，下限 1 ms）。`--json` 时输出的是 **NDJSON**：每收到一块冲一行 JSON，收尾再冲一行带 `"done":true` 的汇总。
- `record` 把收到的数据**原样落盘**：不解码、不转义、不补换行，字节级一致，事后能直接拿去比对原始报文。`--out` 指定路径，不给就用默认文件名 `stui-record-YYYYMMDD-HHMMSS.mmm.log`（落在**当前目录**，精确到毫秒，同一秒里跑两次不会撞名）；`--duration` 是录制时长（毫秒，默认 5000，给 `0` 表示不设上限，录到进程被结束）；`--format ndjson` 时每块冲一行 JSON，`--json` 的汇总行给出 `port` / `out` / `bytes` / `chunks` / `elapsed_ms`。**`--json` 与 `--format text` 不能同时给**（退出码 2）：`--json` 时 stdout 全是 JSON 行，`--format text` 的每块数据是人看的文本，混在一起会让按行解析的下游崩掉。
- `record --stdout` 在落盘之外，把收到的字节**再原样冲一份到 stdout**（字节级，不加任何东西），于是 `stui record --port COM3 --duration 5000 --stdout > raw.bin` 直接就是原始报文。stdout 被原始字节占住时，逐块的可读输出与最后的汇总行改走 **stderr**。**`--stdout` 与 `--json` 不能同时给**（退出码 2）：stdout 上混着原始字节与 JSON 行，按行解析的下游会崩。`--stdout` 与 `--out` 可以同时给（一个落盘、一个冲 stdout）。
- `selftest` 用内置 sim 回环自检整条链路，**不碰真实串口、不起子进程**：三项检查 —— `sim-open`（回环设备能打开）、`echo-match`（第一段已知报文回显逐字节一致）、`no-crosstalk`（再发一段不同报文，回显仍是第二段）。全过退出码 `0`，有一项不过就是 `1`。

### JSON 输出与退出码

```bash
$ stui list --json
{"ok":true,"count":1,"ports":[{"port":"COM26","desc":"USB-SERIAL CH340 (COM26) wch.cn","kind":"usb","manufacturer":"wch.cn","product":"CH340"}]}

$ stui send --port sim --text "hi\r\n" --json
{"ok":true,"port":"sim","baud":115200,"sent":4,"received":4,"rx_hex":"68690D0A","rx_text":"hi\u000D\u000A","elapsed_ms":520,"expect_ok":true,"expect_hex":"","expect_checked":false,"expect_missing":[]}

$ stui send --port sim --text "hi" --expect "6869" --json
{"ok":true,"port":"sim","baud":115200,"sent":2,"received":2,"rx_hex":"6869","rx_text":"hi","elapsed_ms":520,"expect_ok":true,"expect_hex":"6869","expect_checked":true,"expect_missing":[]}

$ stui send --port sim --text "hi" --expect "FF" --json     # 退出码 5
{"ok":false,"error":"期望的响应未出现","port":"sim","baud":115200,"sent":2,"received":2,"rx_hex":"6869","rx_text":"hi","elapsed_ms":520,"expect_ok":false,"expect_hex":"FF","expect_checked":true,"expect_missing":["FF"]}

$ stui send --port sim --text "hi" --expect "6869|FF" --json   # 退出码 5：缺了第二段
{"ok":false,"error":"期望的响应未出现","port":"sim","baud":115200,"sent":2,"received":2,"rx_hex":"6869","rx_text":"hi","elapsed_ms":520,"expect_ok":false,"expect_hex":"6869,FF","expect_checked":true,"expect_missing":["FF"]}

$ stui listen --port sim --timeout 300 --json
{"ok":false,"error":"timeout","port":"sim","received":0,"rx_hex":"","rx_text":"","elapsed_ms":300}

$ stui watch --port sim --timeout 300 --json
{"ok":true,"t":1760000000123,"len":2,"rx_hex":"6869","rx_text":"hi"}
{"ok":true,"done":true,"total":2,"chunks":1,"elapsed_ms":300}

$ stui record --port sim --duration 300 --out rec.bin --json
{"ok":true,"port":"sim","out":"rec.bin","bytes":2,"chunks":1,"elapsed_ms":300}
```

| 退出码 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1` | 未预期的运行错误 |
| `2` | 参数错误或内容解析失败（如十六进制位数为奇数） |
| `3` | 串口打开失败 |
| `4` | `listen` 超时未收满 |
| `5` | **响应与期望不符**：`send --expect` 没能等到期望的字节序列 |

新增的子命令（`watch` / `selftest` / `record`）与新参数（`ports` 别名、`--dry-run`、`--kind`、`--verbose`、`--expect`、`--format`）**沿用同一套退出码**：参数写错一律 `2`，串口打不开一律 `3`，收发过程中出错一律 `1`，成功一律 `0`；只有 `listen` 收不满时会用 `4` 表示超时；只有 `send --expect` 等不到期望响应时会用 `5`（单独给一个码而不是复用 `1`，脚本才能区分「操作失败」与「操作成功但结果不符合预期」——后者多半说明设备在回别的东西，是调参问题而不是环境问题）。

本轮新增的能力**没有引入新的退出码**，全部复用上面这套：`--expect` 的多段写法里有非法段仍是 `2`（参数错误，不是「期望不符」）；`listen --save` / `record --stdout` 写文件失败是 `1`；`--stdout` 与 `--json` 互斥、`--expect` 没给就单独给 `--expect-timeout`，都是 `2`；期望对不上仍然是 `5`。

`--json` 模式下错误也走 stdout 且带 `"ok":false`，方便调用方无条件解析；非 JSON 模式下错误写 stderr。

### 给 AI 的调用建议

1. 先 `stui list --json` 拿到端口名，再决定 `--port`。
2. 需要确认链路时优先用 `--port sim` 做一次自检（不发真实报文）。
3. 判定结果用退出码，提取内容用 `rx_text` / `rx_hex`，不要解析人类可读输出。
4. `listen` 抓数据时把 `--bytes` 设成期望长度、`--timeout` 设成可接受等待，配合退出码 4 判断"没等到"。
5. 拿不准参数怎么写时，先跑 `stui selftest --json`：它只碰内置回环设备，不会误发真实报文，能一次确认运行环境是通的。
6. 只想知道「会发什么」而不想真发出去时，用 `stui send --dry-run --text ... --json` 看 `planned_hex`。
7. 要确认设备「按预期回包」时用 `stui send --port ... --expect "4F 4B" --json`：回包匹配退出码 `0`，不匹配退出码 `5`（**不是** `1`），一眼分得清「设备没回」与「设备回了但内容不对」。设备会回好几段时用 `--expect "4F 4B|4F 4C"`（段与段之间用竖线），**必须全部命中**才算通过，差哪几段看 JSON 里的 `expect_missing`。
8. 要把一段原始报文留档时用 `stui record --port ... --duration 5000 --out raw.bin`：文件里是字节级原样数据，不解码、不转义，事后能直接拿去比对。
9. 只想收一段数据、同时留下原始文件时用 `stui listen --port ... --bytes 64 --timeout 2000 --save raw.bin --json`：结果里的 `out` 字段给出保存路径。
10. 想把收到的原始字节直接接进管道时用 `stui record --port ... --duration 5000 --stdout > raw.bin`：stdout 上只有字节，汇总行走 stderr；此时不要再加 `--json`。

## 记录文件

`logs/stui-YYYYMMDD-HHMMSS.log`（UTF-8），每行一条：

```
[2026-10-15 21:41:02.118] RX  48 65 6C 6C 6F 20 57 6F 72 6C 64  |Hello World|
[2026-10-15 21:41:05.984] SYS PONG 1
```

接收与发送记为十六进制并附预览栏（同样按 UTF-8 解码），系统事件记原文，便于事后复盘。

这是 TUI 里按 `l` 记录的日志。CLI 的 `stui record` 是另一回事：它把收到的字节**原样**写进 `--out` 指定的文件（没有时间戳、没有十六进制列），录多久由 `--duration` 决定。

## 配置持久化

启动时读取、退出时写回一份扁平 JSON，位置是：

| 平台 | 路径 |
| --- | --- |
| Windows | `%APPDATA%\stui\config.json` |
| Linux / macOS | `$XDG_CONFIG_HOME/stui/config.json`，没有 `XDG_CONFIG_HOME` 时退回 `~/.config/stui/config.json` |

内容只记**端口与参数**，外加六个开关：

```json
{"version":1,"port":"COM25","baud":115200,"bits":8,"parity":"none","stops":1,"flow":"none","view":"text","interval_ms":1000,"fps":20,"auto_reconnect":false,"show_ms":true,"wrap":false,"auto_ports":true,"filter_ci":false,"filter_invert":false}
```

| 开关 | 含义 | 默认 |
| --- | --- | --- |
| `auto_reconnect` | 掉线后自动重连（界面里 `Ctrl+R`） | 关 |
| `show_ms` | 时间戳显示到毫秒（界面里 `Ctrl+T`） | 开 |
| `wrap` | 长行自动折行（界面里 `w`） | 关 |
| `auto_ports` | 自动刷新端口列表（每 5 秒枚举一次） | 开 |
| `filter_ci` | 过滤**忽略大小写**（界面里 `I`） | 关 |
| `filter_invert` | 过滤**排除匹配**（界面里 `!`） | 关 |

- 启动顺序是「先恢复配置，再让命令行参数覆盖它」：命令行是这一次的明确意图，优先级高于配置里留下的偏好。
- 写回时**先写同目录下的临时文件再改名**，替换是原子的；写到一半断电不会把旧配置变成半截 JSON。
- **配置文件坏掉不能让程序起不来**：读不出来、JSON 解析失败、字段类型不对，一律静默退回默认值（个别字段类型不对时只丢那一项，其余照常恢复）。
- 配置里的端口按**不区分大小写**匹配枚举结果（Windows 上写 `com3` 也能匹配到 `COM3`）；端口当前不存在、波特率不在快捷列表里、帧率越界时保留默认值，并在事件日志里记一条 `SYS` 说明。
- `wrap` 与界面里的 `w` 是**同一个开关**：在界面里折行后正常退出，下次启动还是折行的。
- `auto_ports` 的默认值是**开**，而且**界面上没有开关**（只能靠这一项配置）：文件里没写这个键时（老版本或手写的配置）保持开启；只有文件里明确写了 `false` 才关掉 —— 配置文件分不出「没写」与「写了 false」这两种情况，程序会额外扫一遍配置文件原文里的顶层键名来区分。
- `filter_ci` / `filter_invert` 是**后加**的两个键：配置文件由配置模块负责写，这两个键由主程序在写完配置后**补写到 JSON 对象的末尾**（文件里已经有同名键时不会重复写）。读取时同样区分「没写」与「写了 false」：文件里没写就保留界面默认值（都是关），只有明确写了 `false` 才照办 —— 否则用户在界面上关掉的开关每次启动都会被打开。
- `stui --no-config` 表示「这次别动我的设置」：既不读也不写配置文件。

## 编码约定

| 范围 | 约定 |
| --- | --- |
| 源码 / 文档 / 日志 | UTF-8 无 BOM，行尾 LF（由 `.editorconfig`、`.gitattributes` 约束） |
| Windows 控制台 | 启动时切到代码页 65001 并启用 VT，避免中文乱码 |
| 串口数据 | 按 UTF-8 解码显示；非法字节降级为 `·`（HEX 栏为 `.`），不做编码猜测 |
| CLI `rx_text` | JSON 字符串，控制字符统一写成 `\u00XX`（如 `\r` → `\u000D`、`\n` → `\u000A`），无法解码的字节为 `U+FFFD`；需要精确字节请用 `rx_hex` |

`cargo test` 里包含针对这些约定的断言（解码、列宽、换行切分、截断、CLI JSON 契约），改动显示逻辑时先跑它。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/main.rs` | 终端生命周期（守卫式恢复）、事件循环（含鼠标滚轮事件）、子命令分派、参数解析、Windows 控制台 UTF-8、配置的读与写（含 `auto_ports` / `filter_ci` / `filter_invert` 「没写 vs 写了 false」的区分） |
| `src/app.rs` | 应用状态与全部交互逻辑：连接管理、收发、记录、按键分发、发送历史、自动重连、速率统计、长行折行（含折行行数缓存）、过滤（关键字 / 忽略大小写 / 排除匹配）、过滤命中导航、记录详情弹窗、自动刷新端口列表 |
| `src/port.rs` | 串口抽象：参数枚举、端口枚举、连接与读线程（`Arc<Mutex<Receiver>>`） |
| `src/ui.rs` | 纯渲染层，只读 `App` 状态并绘制；含折行排版与行数统计、详情弹窗、命中导航定位、过滤高亮与空结果提示、`TestBackend` 离屏渲染测试 |
| `src/fmt.rs` | 时间戳、UTF-8 解码与列宽、换行切分、截断、折行、转义/十六进制解析（CLI 与 TUI 共用）、忽略 ASCII 大小写的匹配与高亮 |
| `src/cli.rs` | 非交互子命令实现（list / ports / send / listen / watch / record / selftest / sim），含 `sim` 虚拟回环设备、多段 `--expect`、`listen --save`、`record --stdout` |
| `src/config.rs` | 配置持久化：手写 JSON 读写 `config.json`（先写临时文件再原子改名），坏配置静默退回默认值；含 `wrap` / `auto_ports` 两个开关 |
| `tests/cli_contract*.rs` | CLI 契约集成测试：退出码、JSON 字段、虚拟设备回环 |

读线程以 100 ms 超时轮询并配合停止标志，关闭串口最多延迟一个轮询周期；缓冲、关闭、异常断开都会同步到状态条与事件日志。

## 已知限制

- 停止位仅支持 1 和 2（serialport crate 未暴露 1.5）。
- HEX 视图的每行字节数随终端宽度自适应（16 / 8 / 4）。
- 文本模式**默认**不按屏宽折行：超长的一行会被截断并标 `…`。按 `w` 可以打开长行自动折行，这时超宽的行按屏宽折成多行；被截掉的内容可以在详情弹窗（数据区按 `Enter`）或 HEX 视图里再看（弹窗正文本身不能滚动，见下）。
- 打开长行折行后，「这条记录占几行」的结果会按「(记录, 折行宽度)」缓存，所以**每帧**的开销不再随缓冲内容线性增长；但**首次**显示（或者改了窗口宽度）时仍要把那条超宽记录重新折一遍才能算出它占几行 —— 一条几千字符的长行要按屏宽扫一遍，这是一次性成本，不是每帧的成本。
- 鼠标**只支持滚轮滚动**：点击、双击、拖拽、横向滚动一律忽略（界面上没有「点哪儿跳哪儿」的交互，自己给这些事件编一套行为只会让人误操作）。滚轮一格固定 3 行，不能在界面里调；终端不支持鼠标捕获时程序会记一条「终端不支持鼠标捕获，滚轮滚动不可用」，这时只能用方向键 / `PgUp` `PgDn`。**详情弹窗开着时滚轮不响应**（这时去滚底下的数据区，用户什么也看不见）。
- 记录详情弹窗里**翻记录**是在「过滤后的序列」里翻的：过滤生效时只在命中的记录之间走，不会跳到被过滤掉的记录上；不过滤时就是全部记录之间走。到头就停住，不循环。
- 记录详情弹窗的**正文不能滚动**：一条超长记录摊开后，超出窗口的那部分看不到（正文滚动的入口还没接按键）。想看完整字节就按 `v` 切 HEX，但 HEX 同样放不下时也只能看到开头一段。
- 过滤命中导航 `n` / `N` 只在**终端页**有效：不在终端页时按下去会提示「切到终端页才能跳到命中的记录」，不会留一个悬着的请求等切回来再突然跳转。跳到头就停住，不循环。
- 自动刷新端口列表**没有界面上的开关**，只能靠配置里的 `auto_ports`（默认开）：每 5 秒枚举一次，列表没变化时不记日志，枚举失败也不记（手动按 `r` 时已经报过一次）。
- 行合并的空闲阈值固定为 180 ms（常量 `RX_IDLE_SEAL`），暂不支持界面内调整。
- 循环发送以主循环 100 ms 为节拍，最小间隔 50 ms，不适合毫秒级时序。
- `watch` 的运行时长**只能靠 `--timeout` 控制**：`--timeout 0`（默认）表示不设截止时间，此时必须由外部结束进程；CLI 没有优雅的 `Ctrl+C` 处理，被中断时不会有收尾汇总行。`--interval` 只是轮询粒度，不参与统计聚合 —— 数据一到就出一行，不会在窗口末尾才吐。
- `record` 同样**只能靠 `--duration` 收尾**（默认 5000 ms，给 `0` 表示不设上限）：没有优雅的 `Ctrl+C` 处理，被中断时不会有汇总行（`bytes` / `chunks` 拿不到）。收到的数据是收到一块就立刻写一块的（不做用户态缓冲），所以被中断时已经写出去的内容不会丢。
- 配置里**只记端口与参数**（端口名、波特率、数据位、校验、停止位、流控、视图、循环间隔、帧率，以及自动重连 / 毫秒 / 折行 / 自动刷新端口列表 / 过滤忽略大小写 / 过滤排除匹配六个开关）：**过滤关键字本身**、输入框内容、发送历史、当前页签都**不会**被保存（存下来的只是两个过滤开关的开关状态）。
- 配置只在**正常退出**时写回；进程被强杀或崩溃时这次设置不会落盘。
- 发送历史只存在内存里（上限 100 条，相邻重复不重复入队），退出即丢；只有**真的把字节写出去**才进历史，没连上或写失败都不记。
- 自动重连连续失败 5 次才记一条日志，中间的失败没有提示；重连只按参数栏里当前选中的端口重试，不会自己在多个端口之间轮询。
- 统计页与帮助页共用同一个滚动位置，在这两页之间来回切时滚动位置会被复位。
- 过滤是**记录级**的：命中的记录整条显示，代价是单条很长的记录不会只显示匹配的那几行。
- 过滤的两个开关（`I` / `!`）在**任何页签**都按得动，但它们只影响**终端页**的数据区：在日志 / 统计 / 帮助页按 `I` / `!` 不会报错，只是当前页看不出变化（统计页的「过滤选项」一行能看到当前状态）。

```bash
cargo test                      # 单元测试 + 命令行契约测试
```
